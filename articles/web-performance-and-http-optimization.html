Web Performance

Optimizing Modern Web Delivery: HTTP/2 Multiplexing, TLS 1.3, and Edge Caching

Published: November 2026 Category: Performance Engineering Reading Time: 10 min

Web performance is dominated by the speed of light in fiber optics and the number of round-trip times (RTT) required before an HTTP response payload begins streaming. Even on gigabit fiber connections, a visitor experiencing 80 ms of network latency must wait through multiple round trips for DNS, TCP handshakes, TLS negotiation, and server compute time.

This article analyzes the network-level mechanics of modern HTTP delivery and outlines practical configuration patterns to achieve sub-100ms Time to First Byte (TTFB).

1. The TLS 1.3 Handshake Advantage

In legacy TLS 1.2, establishing an encrypted session required two round trips: one for cipher negotiation and key exchange, and a second for certificate validation and Finished messages.

TLS 1.3 mandates Diffie-Hellman ephemeral key exchanges directly inside the initial ClientHello and ServerHello packets. This reduces the handshake to a single round trip (1-RTT).

OCSP Stapling

When OCSP stapling is disabled, the client browser pauses connection establishment to query the Certificate Authority's OCSP responder directly. Enabling ssl_stapling on; allows the server to attach a timestamped, signed OCSP response to its TLS handshake, eliminating CA lookup latency entirely.

2. HTTP/2 Stream Multiplexing and Head-of-Line Blocking

Under HTTP/1.1, browsers opened up to six parallel TCP connections per origin to bypass head-of-line blocking. Each connection consumed server memory, required separate handshakes, and competed for TCP congestion windows.

HTTP/2 breaks requests and responses into independent binary frames tagged with a Stream ID. Multiple requests travel concurrently over a single TCP socket.

  • Zero Connection Overhead: Additional asset requests incur no TCP or TLS handshake overhead.
  • Stream Prioritization: The browser can indicate that critical CSS and HTML frames should be delivered before non-critical images.
  • HPACK Header Compression: Repetitive HTTP headers (such as Cookie, User-Agent, Accept-Encoding) are compressed via differential index tables.

3. Compression: Brotli vs. Gzip

Brotli provides 15% to 25% better compression density than Gzip for text assets (HTML, CSS, JavaScript, JSON) thanks to its pre-defined dictionary of common web idioms and longer sliding window size.

However, Brotli levels 10 and 11 are computationally intensive and should only be applied to static pre-compressed assets during build time. For dynamic on-the-fly compression, Brotli level 4 or 5 offers the optimal trade-off between CPU overhead and compression gain. 

# Nginx configuration for high-performance static delivery
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name mehanoid.space;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;

    # OCSP Stapling
    ssl_stapling on;
    ssl_stapling_verify on;
    resolver 1.1.1.1 8.8.8.8 valid=300s;
    resolver_timeout 5s;

    # TLS Session Cache
    ssl_session_timeout 1d;
    ssl_session_cache shared:SSL:10m;
    ssl_session_tickets off;

    # Compression
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml application/json application/javascript application/xml+rss image/svg+xml;

    # Static asset caching
    location ~* \.(css|js|svg|woff2|ico|png|jpg)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform, immutable";
        access_log off;
    }

    # HTML documents: immediate validation
    location / {
        add_header Cache-Control "public, max-age=0, must-revalidate";
    }
}

4. Deterministic Cache-Control Policies

The fastest network request is the one that never touches the network. A bulletproof caching strategy separates assets into two categories:

Resource Type Header Directive Browser Behavior
Hashed Assets (e.g., bundle.a1b2c3.js) public, max-age=31536000, immutable Stored in disk cache for 1 year; browser never checks for updates until URL changes.
HTML Documents public, max-age=0, must-revalidate Browser revalidates ETag/Last-Modified with server before rendering, ensuring fresh deployments.
Private User API no-store, no-cache, private Never written to intermediate caches or client disk.

5. Diagnostic Profiling with curl

Instead of relying on browser DevTools which introduce extensions and local rendering delays, use curl to measure exact socket timing breakdowns: 

curl -w "\n\
DNS Lookup:        %{time_namelookup}s\n\
TCP Connect:       %{time_connect}s\n\
TLS Handshake:     %{time_appconnect}s\n\
Pre-Transfer:      %{time_pretransfer}s\n\
Time to First Byte:%{time_starttransfer}s\n\
Total Duration:    %{time_total}s\n" \
-o /dev/null -s https://mehanoid.space

By systematically addressing each stage—minimizing DNS latency, tuning TLS session resumption, enabling HTTP/2 multiplexing, and enforcing immutable caching—static web delivery achieves predictable, lightning-fast response times globally.
